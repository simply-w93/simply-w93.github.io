Script rules#

  1. A script is a Java source fragment. Do not add package, import, a wrapper class, or extends ScriptDefaults; Raven generates the class/import wrapper.
  2. Use Java 8-compatible syntax.
  3. Use only callbacks and API signatures documented here. Do not invent methods from other Raven versions or Minecraft APIs.
  4. Cancellable callbacks cancel only when they explicitly return primitive false.
  5. getRotations() must return boxed Float[], not float[].
  6. Read this script's registered settings with scriptName, e.g. modules.getButton(scriptName, "Enabled").
  7. Guard player/world-dependent calls with client.getPlayer() != null and/or world.exists().
  8. client, world, modules, render, gl, inventory, keybinds, config, util, and bridge are provided by Raven. modules is bound to the current script; bridge is shared globally.
  9. Direct keystrokesmod.* access is internal/unstable and is intentionally not treated as the normal scripting API here.

Runtime#

  • Scripts are loaded from <minecraftDir>/keystrokes/scripts.
  • Only .java files are parsed; files beginning with _ are ignored.
  • The filename without .java becomes the module name and global scriptName.
  • Raven compiles at runtime with ToolProvider.getSystemJavaCompiler(), so a JDK is required.
  • This beta targets Minecraft 1.8.9, MCP stable 22, and a Java 8 toolchain.
  • onLoad() runs after compilation/loading and after Raven attaches its own Script name setting. Event callbacks require the script module to be enabled.
  • A top-level line load - "https://..." is expanded before compilation only when the Manager's HTTP setting is enabled.

Automatic imports in this beta are: Color, Collections, List, ArrayList, Arrays, Map, Set, HashMap, HashSet, ConcurrentHashMap, LinkedHashMap, LinkedHashSet, Iterator, Comparator, AtomicInteger, AtomicLong, AtomicBoolean, Random, Matcher, plus keystrokesmod.script.model.*, keystrokesmod.script.packet.clientbound.*, and keystrokesmod.script.packet.serverbound.*.

Script sandbox#

The generated script is loaded through SecureClassLoader. Allowed package prefixes are sun.reflect, keystrokesmod, java.lang, java.util, and java.awt, but these classes are explicitly blocked even though their packages are otherwise allowed: Runtime, Process, ProcessBuilder, ProcessHandle, System, Class, ClassLoader, Thread, ThreadGroup, SecurityManager, Compiler, Package, Module, java.awt.Desktop, java.awt.Robot, and java.awt.Toolkit. Exception/Throwable classes and generated sc_* script classes are also accepted by the loader. Prefer the scripting wrappers instead of native Minecraft classes.

Minimal script#

JAVA
void onLoad() {
    modules.registerButton("Show HUD", true);
}

String getSuffix() {
    return modules.getButton(scriptName, "Show HUD") ? "On" : "Off";
}

void onRenderTick(float partialTicks) {
    if (!modules.getButton(scriptName, "Show HUD")) return;
    render.text2d("Hello", 8, 8, 1.0f, 0xFFFFFFFF, true);
}

Callback notes#

  • String getSuffix() supplies the module HUD info suffix. null becomes an empty suffix. Keep it cheap because HUD code may query it repeatedly.
  • boolean onChat(String message, int type), onPacketSent, onPacketReceived, onPreAttack, onAttackEntity, onKeyPress, onMouse, and onPreRenderModel cancel when they return false.
  • Float[] getRotations() may return one element (yaw) or two (yaw, pitch); either element may be null. Length 0 or >2 is ignored.
  • onPrePlayerInput(MovementInput) and onPreMotion(PlayerState) are mutable: Raven copies changed fields back into the underlying event.
  • onWorldJoin(Entity) fires for every EntityJoinWorldEvent, not only the local player's server join.
  • Mouse wheel events arrive through onMouse with button == -1; positive wheel delta maps to state=true, negative to false.

Namespaces#

client#

Role

client is the high-level bridge to the local Minecraft client and local player. It covers player state, movement input, motion, rotations, packet dispatch, chat, GUI state, raycasts, resource packs, timing, and a handful of client utilities.

It is intentionally broad. Treat it as the default namespace for operations whose owner is the local client or local player rather than the loaded world.

Player safety
Most methods dereference mc.thePlayer directly. client.getPlayer() is one of the few methods with an explicit null guard, so scripts should guard player-dependent work after disconnects and during world transitions.
Coordinates
Motion is returned as world-axis X/Y/Z. Raycast block hits return block position plus a hit offset relative to that block; entity raycasts return the entity, an offset relative to its position, and squared eye-to-hit distance.
Packets
sendPacket goes through the normal outbound queue. sendPacketNoEvent uses Raven's no-event helper. Inbound processPacket processes the wrapper's backing native packet directly.
Threading
async(Runnable) lazily creates a cached thread pool. sleep(int/long) blocks whichever thread invokes it; do not use sleep in render/update callbacks when frame or tick responsiveness matters.

Movement & player state

  • setJump, setSneak, setForward, and setStrafe write movement-input fields.
  • setJumping, setSneaking, setSprinting, and setFlying write entity/capability state instead.
  • setMotion replaces all three motion components; multiplyMotion multiplies only X and Z.
  • setTimer writes Minecraft's timer speed and is not automatically restored by the API.

Rotation helper

  • setRotations, setYaw, and setPitch operate through Raven's shared RotationHelper.
  • getServerYaw() and getServerPitch() return boxed Float values and may therefore be null.
  • enableMovementFix() forces Raven's movement-fix path; disableMovementFix() clears that force flag.
  • getServerDirection(PlayerState) simply returns state.yaw in this beta.

Chat, UI & local display

  • chat sends a chat message through the local player to the server; print is local chat output.
  • setTabName searches the current tab-list profile names case-insensitively and changes the first matching entry's local display component. It does not rename the server-side profile.
  • getScreen() returns the current GUI class simple name, or an empty string when no screen is open.
  • closeScreen() special-cases Raven's ClickGui; otherwise it delegates to the player's normal close-screen call.

Raycasts & placement

  • raycastBlock returns null when no block is hit; otherwise { Vec3 blockPos, Vec3 hitOffset, String sideName }.
  • raycastEntity tests collidable living entities and returns { Entity, Vec3 hitOffset, double squaredDistance }, or null.
  • canPlaceBlock requires an ItemStack wrapper whose backing item is a block. Facing strings are resolved against Minecraft's EnumFacing.
  • placeBlock uses the local held item and forwards to onPlayerRightClick.

Runtime & diagnostics

  • nanoTime() and time() expose System.nanoTime() and System.currentTimeMillis().
  • getTotalMemory, getFreeMemory, and getMaxMemory expose JVM runtime memory values in bytes.
  • getUID() is hard-coded to 4 in this beta.
  • getResourcePacks() returns String[]{name, description} entries in reversed repository order; the default pack is returned with an empty description when no repository entries are active.

Friend / enemy lists

  • addFriend, removeFriend, isFriend use Raven's friend utility.
  • addEnemy, removeEnemy, isEnemy use the corresponding enemy list.
  • These calls operate on Raven client-side lists, not server teams or tab-list data.

world#

Role

world exposes loaded-world state: blocks, entities, network players, scoreboard/tab information, teams, tile entities, sounds, title text, and Raven's client-only entity manager.

Unlike client, this namespace is about data owned by the currently loaded world. Several methods assume a world exists even when world.exists() is available, so use that guard around world-dependent callbacks.

World absence
getDimension() returns "" and getEntities() returns an empty list when no world is loaded. Other calls, including teams, player entities, and tile entities, dereference the world directly.
Scoreboard
getScoreboard() returns Raven's sidebar lines, but returns null rather than an empty list when no lines are available.
Titles
setTitleText forwards directly to GuiIngame.displayTitle. Fade-in, display, and fade-out values are integer tick counts. clearTitleText() calls the same native method with null text and -1 timings.
Entity wrappers
Loaded/native entities are converted to scripting Entity wrappers. getEntityById returns null when no world/entity is found.

Blocks & dimensions

  • getBlockAt accepts integer coordinates or Vec3. If Raven's block-state lookup returns null, the API returns an air Block wrapper at that position.
  • getDimension() returns the provider's display dimension name, not a numeric dimension ID.

Tab list, teams & scoreboard

  • getNetworkPlayers() converts Raven's tab-list data to NetworkPlayer wrappers.
  • getTabHeader() and getTabFooter() return unformatted text and fall back to "".
  • getTeams() maps each scoreboard team's registered name to a copied list of member names.

Client-only mobs

  • spawnMob delegates to a static ClientEntityManager; spawned mobs exist only in the local world and are assigned negative entity IDs.
  • Type input is normalized by trimming/lowercasing, removing a leading minecraft:, and ignoring underscores, dashes, and spaces. The manager also defines aliases such as wither, irongolem, snowgolem, pigzombie, and mooshroom.
  • clearClientEntities() clears the manager globally, not per script. Prefer removeClientEntity(entity) for script-owned cleanup.

Known beta behavior

  • isValidEntity(Entity) checks the native world's loaded-entity list using the wrapper object itself. Because that list contains native entities, this check is not reliable in this beta.
  • playSound uses the world sound call at the exact supplied coordinates with the final distance-delay parameter set to false.

Client-side mobs#

JAVA
Entity mob = world.spawnMob("Zombie", 0.0, 64.0, 0.0);
if (mob != null) {
    mob.moveTo(2.0, 64.0, 2.0, 90.0f, 0.0f, 5);
}

spawnMob is client-only and returns null on failure. It accepts registered living-entity names after trimming, lowercasing, removing a leading minecraft:, and ignoring _, -, and spaces. Extra aliases are: wither -> WitherBoss, irongolem -> VillagerGolem, snowgolem -> SnowMan, mooshroom -> MushroomCow, zombiepigman -> PigZombie, magmacube -> LavaSlime, ocelot -> Ozelot, horse -> EntityHorse.

Spawned entities receive negative client entity IDs. The manager tracks them globally across scripts. world.removeClientEntity(entity) removes only entities created by this manager. world.clearClientEntities() removes all currently tracked client entities, including ones created by other scripts, and resets the generated ID counter. There is no automatic per-script cleanup. Calls made off the Minecraft client thread are scheduled onto the client thread and wait for the result. Prefer per-entity cleanup in onDisable() and onDisconnect().

modules#

Role

modules is the bridge between scripts and Raven's module/setting system. Raven binds this object to the current script, which is why registration calls can attach settings without taking a module name.

Use scriptName when reading or mutating settings registered by the current script. Module and setting lookups are direct map/name lookups in the source; do not assume fuzzy matching.

Module lookup
enable/disable silently do nothing for unknown modules. isEnabled and isHidden return false when the target module is missing.
Setting lookup
Settings are matched with setting.getName().equals(settingName), so setting names are exact/case-sensitive in this implementation.
Typed getters
Button, slider, key, and color getters cast the found setting directly to the expected setting class. Using the wrong getter for an existing setting can throw ClassCastException.
Missing settings
When the correctly typed setting is absent: buttons/keys return false, sliders/min/max return 0, colors return 0, and string-slider values return "".

Registering script settings

  • registerGroup creates a visual group setting; grouped overloads find a group by exact name within the current script.
  • Numeric sliders support optional suffix, minimum, maximum, and interval. String sliders store an integer-like slider position and an option array.
  • registerDescription adds display-only text. It is not included in getSettings().
  • Color registration has RGB and RGBA overloads, with grouped and ungrouped variants.

Reading and mutating settings

  • getSliderString rounds the current numeric input to the nearest option index, then clamps it to the options array.
  • setSlider calls setValueRawWithEvent, so Raven's setting-change event path is used rather than a silent field write.
  • getSettings(module) only exports slider inputs, button states, and color values. Key, group, and description settings are omitted.

Module discovery

  • getCategories() is built from the current ClickGui category components and returns category enum names mapped to module names.
  • This is UI-derived state rather than a separately enumerated registry API.

Built-in module integration

  • getKillAuraTarget() returns the current static KillAura target wrapper or null.
  • getBedAuraPosition() returns null unless BedAura exists, is enabled, and has a target position.
  • getBedAuraProgress() returns {progress, 0}; when BedAura is unavailable/disabled it returns {0, 0}.
  • isScaffolding() and isTowering() are hard-coded to false in this beta.

gl#

Role

gl is a thin immediate-mode OpenGL/GlStateManager bridge for custom rendering. It exposes matrix operations, primitive submission, texture binding, color, clipping, lighting, depth/blend/cull state, polygon offset, and generic capability toggles.

This namespace intentionally gives scripts low-level state control. Raven does not provide an automatic state scope around these calls, so state you change can affect subsequent game/client rendering unless you restore it.

Constants
Methods such as begin, enable, disable, and depthFunc take raw OpenGL integer constants. The scripting sandbox does not automatically import GL11, so scripts commonly use the numeric values already known for Minecraft 1.8.9/OpenGL 1.1.
Color overloads
Float/double colors are forwarded as normalized components. The integer overload treats all components ≤ 1 as already normalized; otherwise each component is divided by 255.
Textures
bindTexture(String) constructs a Minecraft ResourceLocation and binds it through the texture manager. bindTextureId(int) binds a raw GL texture ID. getBoundTexture() reads GL_TEXTURE_BINDING_2D.
Matrix stack
push()/pop() directly wrap glPushMatrix/glPopMatrix. Always keep them balanced, especially inside render callbacks.

Primitive drawing

  • Use begin(mode), submit vertex2/vertex3, optional texCoord2/normal, then end().
  • The API does not validate begin/end nesting or whether a submitted operation is legal for the active primitive.
  • lineWidth and lineSmooth change global GL line state.

State switches

  • Convenience toggles exist for alpha, blend, cull, depth, lighting, texture2D, scissor, line smoothing, polygon offset, and depth-mask writes.
  • enable(cap)/disable(cap) route common capabilities through GlStateManager; unknown capabilities fall back to raw glEnable/glDisable.
  • colorMask controls which RGBA channels are writable; restore all four to true unless masking is intentionally persistent.

Polygon offset & depth

  • polygonOffset(float factor, float units) sets the GL offset parameters.
  • polygonOffset(boolean) toggles Raven/Minecraft's polygon-offset state; setting parameters alone does not enable the capability.
  • depthFunc(int) changes the comparison function globally and should be restored after specialized passes.

Scissor coordinates

  • scissor(x,y,width,height) forwards raw window-pixel coordinates to OpenGL; it does not convert Minecraft scaled GUI coordinates or flip Y for you.
  • scissor(boolean) toggles GL_SCISSOR_TEST.
State discipline: a safe custom render pass generally pairs push/pop, begin/end, and restores depth, texture, blend, color-mask, line width, bound texture, and color when those states were changed.

config#

Role

config is a minimal persistent string key/value store backed by one shared text file: <minecraftDir>/keystrokes/script_config.txt.

It is not automatically namespaced per script. Prefix your keys with scriptName when collisions with other scripts would be a problem.

File format
Each entry is written as key: value, one entry per line. The helper creates the parent directory and file when needed.
set()
Rejects null/empty keys, removes literal : characters from the key, replaces the first matching line, or appends a new line. Returns false on I/O failure.
get()
Rejects null/empty keys and returns null for missing keys or I/O failure. Unlike set, it does not sanitize colons from the lookup key.
Concurrency
Every operation reads/writes the file directly. There is no source-level synchronization or transactional layer around concurrent async writes.

render#

Role

render provides the opinionated drawing layer above gl: block/entity overlays, 2D and 3D text, rectangles/gradients, lines, tracers, item/entity GUI rendering, images, world-to-screen projection, theme colors, and post-process blur/bloom helpers.

Prefer this namespace for common visuals; drop to gl only when the higher-level renderer does not expose the primitive or state you need.

Color format
Render helpers consume packed Java ARGB integers. Alpha is the high byte, followed by red, green, and blue.
World overlays
entity interpolates the target from last-tick to current position using the supplied partialTicks, expands its bounding box by 0.1, and draws with depth disabled. line3D likewise disables depth while drawing.
Projection
worldToScreen subtracts render-manager viewer coordinates, reads the current model/projection/viewport matrices, runs GLU.gluProject, and returns Vec3(screenX, screenY, projectedDepth) or null.
Theme lookup
getThemeRGB(theme) resolves the string to the Theme enum then requests gradient position 0. The enum lookup is exact/case-sensitive and invalid names can throw.

2D drawing

  • rect, roundedRect, gradientRect, and line2D use GUI/display coordinates.
  • text is an alias of text2d. Coordinates are divided by the requested scale after the matrix is scaled so the apparent x/y location remains in caller-space.
  • getFontWidth uses the Minecraft font renderer plus Raven's additional bold-width calculation; getFontHeight returns the font renderer's constant height.

3D drawing

  • text3d billboard-rotates text against the render manager's player view and translates relative to interpolated player position.
  • The depth parameter is counterintuitive: when true, the implementation disables depth testing/depth writes for the text, so it can draw through geometry.
  • getPosition() returns the render manager's viewer position, not the local player's raw position.

Items, entities & images

  • entityGui only renders wrappers marked as living; non-living entities are ignored.
  • item uses GUI standard item lighting and the wrapped native item stack.
  • image returns immediately for null/unloaded images. The first draw creates a DynamicTexture, caches its GL texture ID in the Image, and uses nearest filtering for the configured texture parameter.

Camera values

  • getRotations() returns { playerViewY, playerViewX } from the render manager.
  • getCameraRotations() returns Raven utility camera yaw/pitch.
  • The partialTicks argument of worldToScreen is present in the signature, but the implementation uses Minecraft's current timer render-partial-ticks when setting up the camera.

Packet API#

Packet callbacks use wrapper classes. Unknown/unmapped packets fall back to generic CPacket / SPacket wrappers containing the native packet and simple class name.

    public String name;
    public net.minecraft.network.Packet packet;

public class SPacket {
    public String name;

  • Send outbound wrappers with client.sendPacket(...) or client.sendPacketNoEvent(...).

Source-verified quirks#

These are implementation facts for this beta and should affect generated code:

  • world.isValidEntity(Entity) checks mc.theWorld.loadedEntityList.contains(entity) using the wrapper, while the list contains native entities. Do not rely on it; prefer ID/world queries.
  • modules.isScaffolding() and modules.isTowering() return false unconditionally.
  • client.getUID() returns constant 4.
  • client.getServerDirection(PlayerState) returns exactly state.yaw.
  • Entity.getServerPosition() wraps raw serverPosX/serverPosY/serverPosZ values; these are not normal world-coordinate doubles.
  • Entity.isInLiquid() returns !entity.isOffsetPositionInLiquid(0, 0, 0), which is counterintuitive.
  • NetworkPlayer.getCape() has no null guard around the cape resource and can throw when no cape exists.
  • A received S12.motion is built directly from the packet's integer motion getters without normalization in the wrapper.
  • The received-packet S14 constructor does not populate onGround.
  • The received-packet S45 constructor dereferences packet.getMessage(); packet modes without a message can be unsafe. Fade timing fields are private.
  • The native-packet C0D wrapper constructor does not populate windowId.
  • The native-packet C13 wrapper constructor does not populate the public ability fields.
  • C0E(windowId, slot, button, mode, itemStack) does not set action; it remains 0 unless assigned before conversion/send.
  • C0F.convert() always creates the native confirm-transaction packet with accepted=true.
  • C03 constructors create the backing native movement packet immediately; later edits to the wrapper's public fields do not rebuild that packet when it is sent.
  • modules typed setting getters perform direct casts and can throw when the wrong getter type is used.
  • world.clearClientEntities() is global to the static client-entity manager, not scoped per script.
  • render.getThemeRGB() is exact/case-sensitive and invalid strings can throw.

Rotation callback#

JAVA
Float[] getRotations() {
    Entity player = client.getPlayer();
    if (player == null) return null;
    return new Float[]{player.getYaw() + 15.0f, null};
}

HTTP JSON#

JAVA
void loadData() {
    client.async(() -> {
        Response r = new Request("GET", "https://example.com/data.json").fetch();
        if (r == null || r.code() < 200 || r.code() >= 300) return;
        Json j = r.json();
        client.print(j.toString());
    });
}

Script checklist#

Before generating a Raven bS script:

  • no package/wrapper class was added;
  • every callback matches an exact documented signature;
  • cancellable callbacks return primitive boolean on every path;
  • getRotations() uses exact spelling and returns Float[];
  • own settings are addressed with scriptName;
  • nullable world/player/item/raycast/network results are guarded;
  • client-side mobs are removed individually when owned by one script;
  • world.setTitleText(...) is used, not world.displayTitleText(...);
  • gl.bindTexture(String) is treated as void;
  • theme names use exact enum constants;
  • raw GL state is balanced/restored;
  • packet enum strings use exact native enum names;
  • no method is inferred from another Raven version or vanilla Minecraft.
